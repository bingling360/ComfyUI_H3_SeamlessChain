# ComfyUI_H3_SeamlessChain

MiniMax H3 多段视频**段间引导（无缝续拍）**单节点插件。

一个节点搞定：多段提示词 → 逐段采样 → 段间无缝续接（视频 + 音频双流）→ 裁剪拼接 → 输出完整 `IMAGE + AUDIO`。

## 原理（一句话）

生成第 N+1 段时，把第 N 段结尾 `context_frames` 帧从**采样输出的 latent 里直接切片**（不解码、不重编码 → 零颜色漂移），按官方 conditioning 协议（`minimax_keyframes`，锚 `resolved_frame_index=0`）钉在第 N+1 段头部，采样每步重注入，顺着上段尾部的运动轨迹继续画；解码后裁掉头部重叠桥再拼接 → 接缝处自然连贯。

## 特点

- **官方原生协议，零 monkey-patch**：conditioning / latent 构造直接调用官方 `MiniMaxH3ImageToVideo` / `MiniMaxH3ReferenceToVideo`，采样走官方 `common_ksampler`，抗 ComfyUI 升级。
- **零额外依赖**：requirements.txt 为空。只用 ComfyUI 自带的 torch 与 comfy 核心，不装 opencv / scenedetect / ffmpeg。
- **无缓存架构**：循环在单次执行内完成，段间 handoff 全是局部变量——旧方案「stale-cache 回放」类 bug 在此架构下不存在。
- **音频双流续接**：guide 同时钉入上段尾部的音频窗（需新版 ComfyUI，见下）。
- **逐段审片**：「审片模式=逐段确认」时每次运行只生成一段新内容即返回，预览满意再重新运行继续下一段——长片不必整链跑完才发现坏段。
- **任意段重跑**：改了第 N 段提示词 → 重跑自动从第 N 段重做（其后段因锚定依赖级联重做，前段沿用断点）；不改词想重摇时用「重跑起始段」+ 换种子。
- **「长片审片」侧栏面板**：ComfyUI 左侧新增面板（旧版前端为悬浮按钮），从**开拍前**到多集连拍全程可用——项目列表切换 / 新建项目（提示词沿用作底稿）、跑前空卡片填写提示词、＋ 添加一段、📎 上传插入视频，跑后逐段内嵌播放器 + 种子 + 接缝/桥分，「继续下一段 / 重摇此段 / 改词重跑」一键完成；数据走 ComfyUI 自带 `/api/view` 与 `/upload/image`，零自建路由、零新依赖。
- **序章续拍**：上传一段现成视频（≥5 帧、24fps）接「起始视频」，编码为第 1 段进断点——成片以它开头，生成段从它的结尾无缝续拍。
- **插入视频**：「插入视频」控件每行一条 `位置|文件名`，把上传到 input 目录的现成视频作为独立段插进**任意位置**（位置 1 = 片头，尾插合法）——片头 / 广告 / 转场素材与生成段混排成片；换文件或增删插入段，其后的段落自动重做（哈希链定位）。
- **断点续跑**：「断点续拍=自动续跑」时每段采样后立即落盘 latent 断点（约 5MB/段），中断重跑自动跳过已完成段，结果与一次跑完**逐帧一致**（同参数下）。
- **桥帧质量门控**：对将成为重叠桥的尾帧打分（Laplacian 清晰度 + 曝光），尾帧低质时可自动回退 17/34 帧取好帧续拍（等价于剪掉坏尾，时间线仍然连续）。
- **接缝后验测量**：每段报告帧差与音频响度跳变（只标注不干预），异常接缝自动提示人工检查。

## 安装

```bash
cd ComfyUI/custom_nodes
git clone <本插件地址> ComfyUI_H3_SeamlessChain
# 或直接把 ComfyUI_H3_SeamlessChain 文件夹拷进来
pip install -r ComfyUI_H3_SeamlessChain/requirements.txt   # 无依赖，可跳过
```
重启 ComfyUI。AutoDL 环境（`/root/miniconda3`）同样步骤，无需额外装包。

## 版本要求

- ComfyUI **≥ v0.30.0**（含官方 MiniMax H3 节点），否则插件不加载并在控制台提示。
- 段间引导的**多帧桥**与**音频锚定**需要 ComfyUI 含 [PR #15439](https://github.com/Comfy-Org/ComfyUI/pull/15439)（2026-08-09 之后构建）。旧版本（如 v0.32.0）的 keyframe 协议每个锚点只收单帧 latent，插件会在运行时自动探测：不支持时自动降级为**单帧桥 + 仅视频引导**（报告中注明，接缝质量受限）。**升级 ComfyUI 后无需改任何参数，自动恢复完整引导帧数**；r2v 链在旧版本上引导还会与参考素材冲突失效，务必升级。

## 使用（节点界面为中文）

1. 按官方 MiniMax H3 工作流加载模型：
   - **UNET**：t2v / i2v 用 `minimax_h3_fl2va_*`；r2v 用 `minimax_h3_ref2va_*`
   - UNET → 官方 **ModelSamplingMiniMaxH3**（shift video 12 / audio 3）→ 本节点「模型」
   - **CLIP**：type 必须选 `minimax`（Qwen3-VL）→ 本节点「文本编码器」
   - 视频 VAE（`minimax_h3_video_vae`）→「视频VAE」；音频 VAE（`minimax_h3_audio_vae`）→「音频VAE」
2. **每段提示词独立输入**：「提示词组」按段展开（提示词_1、提示词_2 …），可以直接写在框里，也可以接 `PrimitiveStringMultiline` 等外部节点；**一个输入框 = 一段视频**，段顺序按编号，点输入区旁的 + / - 增减段（最多 64 段）。
3. **参考素材（r2v 链）**：四组 autogrow 输入，用法与官方 Reference to Video 完全一致——
   - 「参考图片组」最多 **9 张**（`<Picture i>` 引用）
   - 「参考视频组」最多 **3 个**（`<Video k>` 引用）：接 `LoadVideo` 的 `frames` 输出
   - 「参考视频音轨组」：与同号参考视频配对（参考视频音轨_0 配 参考视频_0），接同一个 `LoadVideo` 的 `audio` 输出，自动获得 `<Audio j>` 标签
   - 「参考音频组」最多 **3 条**独立音频（配乐/音效，`<Audio j>` 引用）：接 `LoadAudio` / `LoadVideo`
   - 标签编号**按连接顺序从 1 数**（官方语义）；中间留空的输入框会被自动压实跳过，不会错位
   - 接了任一参考素材 → 整条链走 r2v，请换 `ref2va` UNET，且不要再接「首帧图片」
4. 输出：「图像」「帧率」「音频」接官方 `Create Video` → `Save Video`；「报告」可右键预览每段执行摘要。
5. **分段单独保存**：「分段图像」「分段音频」为逐段展开输出（`OUTPUT_IS_LIST`），再接一组 `Create Video` → `Save Video`，运行时每段各存一个视频文件（自动编号），内容与成品中该段的画面完全一致，方便逐段检查或自行剪辑；不需要时该支路删掉即可，不影响成品输出。

### 任务链自动判定（无需选 task_type）

| 连接 | 链路 | UNET |
|---|---|---|
| 什么都不接 | 纯 t2v | fl2va |
| 「首帧图片」 | 首段 i2v + 续段 t2v | fl2va |
| 「起始视频」（+ 可选音轨） | 序章（上传视频）+ 续段 t2v | fl2va |
| 任一「参考」组 | 每段 r2v（提示词用 `<Picture i>` / `<Video k>` / `<Audio j>` 引用），可与序章共存 | ref2va |

### 关键参数（均为节点上的中文控件名）

- `每段帧数`：每段**可见**帧数 @24fps（124 ≈ 5 秒，模型训练范围约 124–362）。段 2 起实际采样帧数自动对齐到 `可见 + 引导帧数` 的 17k+5 网格。
- `引导帧数`：段间重叠桥，只能取 5 / 22 / 39 / 56（模型 17k+5 帧网格点）。越大衔接越顺、越慢越吃显存，默认 22。
- `种子`：每段自动 +1（段 i 用 `种子 + i`）。
- `审片模式`：默认关闭；「逐段确认」= 每次运行只生成一段新内容即返回（见下节）。
- `重跑起始段`：默认 0 = 自动（沿用断点进度，改过提示词的段自动重做）；N = 从第 N 段起重做（见下节）。
- 默认采样参数：25 步、res_multistep + simple、CFG 1.0（蒸馏模型）。

### 断点续拍（长片防跑废）

- `断点续拍=自动续跑`：每段采样完成即写 `output/checkpoints/<断点目录>/seg_NNN.pt`（AV latent）+ `manifest.json`（原子写，含逐段种子 / 提示词哈希 / 裁剪量）。第 k 段崩溃后**原参数重跑**，前 k 段自动从断点载入重解码（秒级），从第 k+1 段继续采样。
- 断点目录默认按**共享参数**（分辨率 / 段长 / 引导帧 / 采样参数等，不含提示词）指纹自动命名；`断点目录` 控件可指定固定名。**改共享参数会拒绝续跑**（报错提示开新链）；改某段提示词不再换链，而是自动从该段重做（见「任意段重跑」）；删掉某个 `seg_NNN.pt` 则该段起重采样。
- 种子以 manifest 记录的**种子序列**为准：种子控件开着自动 +1，续跑 / 审片续接时报告会注明「控件种子仅在重跑起始段 > 0 时生效，当前沿用断点种子序列」——多轮运行与一次跑完逐帧一致。
- 断点为中间产物，全链跑完可整目录删除；想换条新链，清目录或改「断点目录」名即可。

### 逐段审片（长片推荐）

`审片模式=逐段确认`：一次 Queue = 一段新内容，天然适配「生成 → 看 → 确认」节奏，无需任何前端交互：

1. 运行 → 只生成第 1 段即返回。「分段图像 / 分段音频」输出该段视频（接「分段保存」支路预览），主「图像 / 音频」输出当前已完成段的累计成片；报告提示下一步操作。
2. 满意 → **直接重新运行**，自动从断点载入已完成段（秒级），生成第 2 段……依此到末段。
3. 不满意 → 两个选择：
   - 改「提示词_N」后运行 → 自动检测到该段提示词已变，**从第 N 段重做**（沿用原种子，只换词）；
   - 设「重跑起始段 = N」并改「种子」→ 从第 N 段**重摇**（新种子只影响第 N 段及之后，之前的段与种子不变）。
4. 全部段完成后再次运行 → 直接拼装输出完整成片，报告注明「本链已全部完成」。

说明：审片会自动启用断点存档（否则无法跨次运行续接），断点目录规则与上节一致；种子控件自动 +1 不影响结果（种子序列由断点权威记录）；「重跑起始段」确认无误后记得改回 0（报告会提醒）。

### 审片面板（推荐操作入口）

装好插件重启后，ComfyUI 左侧侧栏多一个「长片审片」标签（**播放机图标** 🎬 `pi pi-video`；旧版前端降级为右侧悬浮按钮）。面板是**项目控制台**，从跑之前就能用，不用等第一次运行：

- **项目管理区**（顶部）：历史项目列表（来自 `output/checkpoints/h3chain_index.json`，按最近更新排序，显示 段进度与时间）。点条目 = 把节点「断点目录」切到该项目（共享参数需与其一致，否则后端会提示换链）；「＋ 新建项目」= 起一条新视频链：自动生成目录名（可改），**提示词沿用当前内容作底稿**，改完直接排队即开跑。
- **段落卡片区**：面板直接读画布节点的「提示词组 + 插入视频」控件，按与后端一致的规则拼出**统一段落计划**——跑之前就是一排空卡片（待生成 / 未填写 / 插入段），可逐卡片「✏ 填写提示词」；跑完后卡片合并断点数据：**左侧内嵌播放器逐段播放带声音的分段视频**（或缩略图）、种子、接缝分 / 桥分、提示词摘要。
- **「＋ 添加一段」**：随时新增一个 `提示词_N` 输入（面板自动创建 `PrimitiveStringMultiline` 并连到节点，与示例工作流同形态）。
- **「📎 插入视频」**：卡片上的按钮 = 在该段前插入；卡片列表底部还有「尾部插入视频」。点选本地视频 → 自动上传到 input 目录 → 写入「插入视频」控件（`位置|文件名`）。插入段卡片可「✕ 移除」。
- **状态条 + ▶ 继续下一段**：顶部蓝条显示「已载入段 1–N（断点回放）→ 本次将生成段 N+1，锚定段 N 尾部」；未开跑时按钮显示「▶ 开始生成（共 N 段）」。

四个常见问题的操作路径：

- **怎么确认这次运行接在上一段后面？** 看状态条与已完成段卡片的可播放视频（种子 / 接缝分 / 桥分 / 提示词摘要，所见即所得）。
- **第一段不满意怎么重跑？** 点段 1 卡片「🎲 重摇此段」：面板自动设「重跑起始段=1」+ 随机新种子并排队；运行成功后「重跑起始段」**自动复位为 0**，不用手动改回。
- **后面某几段不满意，想回到前面某段？** 点那一段卡片的「🎲 重摇此段」（该段及之后重做，之前的段与种子原样保留）；或点「✏ 改词重跑」，在面板内直接改这段提示词，保存后自动从该段重做（哈希变化自动定位，无需设任何控件）。
- **想以上传的视频为起点续拍 / 插一段现成视频？** 序章用「起始视频」输入（见下节）；任意位置插入用面板「📎 插入视频」按钮或手写「插入视频」控件。

面板按钮改的都是画布上 `H3SeamlessChainSampler` 节点的控件再排队，与手动操作完全等价；改词写回支持节点内输入框和上游 `PrimitiveStringMultiline` 两种接法。旧断点目录（manifest 缺缩略图 / 分段视频 / 提示词等新键）在**下一次运行时自动补齐**（纯回放也会回写，不重跑采样）；分段视频依赖 PyAV（ComfyUI 新视频栈自带），缺失时面板回退为缩略图，不影响生成。

### 从任意段重跑 / 重摇

- **改词自动重跑**（`重跑起始段=0`）：逐段提示词哈希比对，改了第 N 段 → 首个不一致段即重跑起点，从第 N 段起重做、其后段级联重做（段 N 的锚定依赖段 N-1 尾帧），段 1..N-1 沿用断点 latent，不浪费算力。
- **指定段重摇**（`重跑起始段=N`）：从第 N 段起丢弃存档重新生成，段 N 及之后用**控件种子 + 段号**；不改种子则与原结果一致（等于纯重做），改种子 = 从该段起换随机性。
- 两种方式都只影响所选段之后的内容；共享参数（分辨率 / 段长 / 引导帧 / 采样参数等）改动仍会被拒绝续跑，防止拼出不一致的成片。

### 序章：从上传视频续拍

手头已有一段实拍 / 生成好的视频，想让后面的段落从它的结尾无缝接下去：

1. 接线：`LoadVideo` 的 `frames` → 本节点「起始视频」；同节点 `audio` 输出 → 「起始视频音轨」（不接则序章按静音处理）。
2. 运行：上传视频被编码为**第 1 段（序章）**存入断点（面板上带「片头（上传）」徽标），成片以它开头，第 1 个生成段从它的结尾续拍。
3. 约定：按 **24fps** 处理（与官方参考视频一致）；帧数向下对齐到 17k+5 网格，超过「每段帧数」只取前段；序章经一次 VAE 重编码（报告注明），画面会有极轻微的重编码损失。
4. 换视频 = 换链：序章指纹（帧数 + 首帧统计）写入哈希链，更换上传视频后自动整链重做；序章本身不能「重摇」，面板上两个重跑按钮对序章禁用。画布上断开序章输入（如 bypass `LoadVideo`）后重跑，会自动沿用断点里的序章。
5. 互斥：与「首帧图片」（i2v）不能同时接（同为第 1 段的视觉起点）；与参考素材（r2v 链）可以共存；与「插入视频」位置 1 互斥（两者都是片头，二选一）。

### 插入视频：任意位置混排现成素材

「插入视频」控件（或面板 📎 按钮）把上传到 input 目录的现成视频作为**独立段**插进成片任意位置：

1. 格式：每行一条 `位置|文件名`（如 `2|ad.mp4`），位置为 1-based **全局段号** = 插入到第几段之前——`1` 即片头（等价序章，二选一），`段数+1` 为尾插；允许空行与 `#` 注释。
2. 处理：与序章同规则——按 24fps、≥5 帧、超长只取前「每段帧数」、经一次 VAE 重编码、带音轨则保留（无音轨按静音）；编码为该槽位的段存入断点，其后生成段从它的尾部续拍。
3. 哈希链：插入段指纹（文件名 + 帧数 + 首帧统计）占 manifest 同一槽位序列——**换文件 / 增删插入段，其后的段落自动重做**（其后段的锚点变了必然级联）。
4. 面板操作：未跑段的卡片上有「📎 插视频到段 N 前」，底部有「📎 尾部插入视频」；选文件自动上传 input 目录并写入控件；插入段卡片可「✕ 移除」。手写清单时文件可含子目录（如 `2|myclips/ad.mp4`）。

### 桥帧门控（防坏尾传播）

- `桥帧门控=标注`（默认）：每段结尾打分写进报告（`段2 桥帧总分 21.3 ↓ 低于阈值`），不改行为——先跑几条链看分数分布，再定 `清晰度阈值`。
- `桥帧门控=自动回退`：尾帧总分低于 `清晰度阈值` 时，向前回退 17/34 帧（受 `回退上限` 限制，自动对齐 17k+5 网格）选达标帧构造续拍桥，该段可见输出同步剪短，时间线仍连续；全部档位不达标则保持原尾并在报告警告。
- 回退后该段可见帧数减少 17/34 帧，总时长与「分段保存」的段长度会随之变化，报告逐段注明。

## 示例工作流

- `example_workflows/h3_chain_storyboard_review.json`：**长片审片生产工作流（推荐，综合生态各家之长）**——四段分镜提示词节点 + 审片模式 + 断点续拍 + 桥帧门控标注 + 成片/分段双保存支路 + 图内使用说明，另含一组默认 bypass 的 `LoadVideo → 起始视频/音轨` 序章接线示例（想从上传视频续拍时启用即可）。流程吸收：Contex-Loop 的分镜单与逐段审片门、Motion-Context 的接缝只测不管、Director 的每段即时落盘视频、总控台的生成前打分门控，底座为本项目的 latent 断点引擎。装好即按说明「运行 → 看面板/分段 → 确认 → 再运行」循环到成片。
- `example_workflows/h3_chain_t2v.json`：三段 t2v 续拍（UNET → SigmaShift → 本节点 → Create Video → Save Video），三段提示词各接一个 `PrimitiveStringMultiline`。
- `example_workflows/h3_chain_r2v_official_base.json`：**官方 r2v 模板骨架移植版（优先使用）**——直接以 ComfyUI 官方 `video_minimax_h3_r2v` 工作流为基底改造，模型加载 / CreateVideo / SaveVideo 节点保持官方原样序列化（含 cnr_id / models 元数据），UNET 直连本节点（与官方 r2v 模板一致，无 SigmaShift），并把官方示例参考图（红披风少年 / 机甲龙）沿用为三段提示词示例。节点上四组参考输入（图片×9 / 视频×3 / 视频音轨×3 / 音频×3）均已展开，「参考视频_0 + 参考视频音轨_0」预接了 `LoadVideo` 的 frames/audio 双输出演示接法；已含「分段保存」支路（每段单独存一个视频）。

## 已知边界（V1）

- 不含 fl2v 尾帧组、v2v / rv2v 源视频编辑（属内容生成方式扩展，非段间引导核心，可后续加）。
- 音频锚定为官方「从锚点向后展开」语义；有节拍的音乐接缝处如察觉轻微不自然，可尝试把 `引导帧数` 提到 39 或 56。
- 旧版 ComfyUI（不含 PR #15439）上第二段起报 `shape mismatch: value tensor of shape [2835, 96] cannot be broadcast to indexing result of shape [405, 96]`：旧 keyframe 协议只收单帧 latent 所致，现已自动降级为单帧桥规避（报告注明）；升级 ComfyUI 可恢复完整桥。
- 旧版（v1）断点目录不兼容本版本（报错并提示换目录名），需重新开链。
- 审片模式下主「图像 / 音频」输出为**已完成段的累计成片**（未完成链不是最终成品）；完整成片在全部段确认完毕后的那次运行输出。
- 「分段图像 / 分段音频」是列表输出：下游 `CreateVideo → SaveVideo` 会**每段各执行一次**，节点预览框因此只显示其中一段（ComfyUI 列表批处理的固有行为，不是丢段）——全部分段视频都按编号存进了输出目录，逐段审看请用「长片审片」面板的内嵌播放器。

## 参数与铁律速查（来自官方）

- 引导帧数必须踩 5 / 22 / 39 / 56 网格点，其他值直接报错。
- CLIP type 必须选 `minimax`（Qwen3-VL）。
- t2v / i2v → fl2va UNET；r2v → ref2va UNET，两种 UNET 别混接。
